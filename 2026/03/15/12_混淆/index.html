花指令

概念：

花之令是为了干扰反汇编器（IDA、objdump 等）而在代码段插入的垃圾代码或不完整指令，能导致反汇编报错或生成错误的控制流。
对于只会按 F5（IDA 全量反汇编）的人来说，花之令可能是致命的分析障碍。

分类

  • 可执行花之令：插入看似合法的指令或数据（不破坏执行），但干扰线性或递归分析。
  • 不可执行花之令：插入不完整或非法的指令序列，使反汇编器在解析时出错。

反汇编算法（简述）

  • 线性扫描（linear sweep）：逐字节解析，无法区分代码与数据，因此容易把嵌入的数据当作指令，导致反汇编报错或混乱。
  • 递归下降（recursive descent，IDA 默认）：从入口或函数边界开始，沿控制流跟踪指令。可以通过构造互补条件、永真/永假跳转等方式，使递归下降产生错误路径或遗漏真实代码。
    所以线性扫描导致的花之令的出现,来混淆代码

常用的花之令构造方式

  1. 在代码段中直接插入数据字节（例如：0xE8 是 call 的 opcode），让线性算法误判为指令或跳转目标。
  2. 构造相互冲突的条件跳转（例如 jz 与 jnz 指向相同的位置,造成冲突），或让一个分支指向无效数据，干扰递归下降。
  3. 永真/永假条件跳转：让某条路径必定被执行或永远不执行，从而隐藏/暴露代码块。
  4. 使用 call/ret 或call+pop 等配合：
    • call 会把返回地址压栈，配合pop可以消除压栈，从而利用 call 实现类似 jmp 的跳转。
    • 利用 call 将控制流临时转移到含有花指令的地方，再通过 ret/调整栈恢复。
    •   .text:0000000000400BB7                 call    loc_400BBF
  .text:0000000000400BB7 ; ---------------------------------------------------------------------------
  .text:0000000000400BBC                 db 0E8h, 0EBh, 12h
  .text:0000000000400BBF ; ---------------------------------------------------------------------------
  .text:0000000000400BBF
  .text:0000000000400BBF loc_400BBF:                             ; CODE XREF: .text:0000000000400BB7↑j
  .text:0000000000400BBF                 pop     rax
  .text:0000000000400BC0                 add     rax, 1
  .text:0000000000400BC4                 push    rax
  .text:0000000000400BC5                 mov     rax, rsp
  .text:0000000000400BC8                 xchg    rax, [rax]
  .text:0000000000400BCB                 pop     rsp
  .text:0000000000400BCC                 mov     [rsp], rax
  .text:0000000000400BD0                 retn
  
  ; 可以看一下，call 指令指令后会将 下一条的地址给储存到栈里，然后从栈踢出加1，最后入栈，retn的，所以实际上的执行流就是400BBC + 1 = 400BBD开始执行，将前面的到call指令全部NOP

手动清除花之令（IDA 中常用步骤）

  1. 找到可疑区域：观察反汇编报错、代码跳转目标为数据区、或出现不合理的指令序列。
  2. 暂时用 NOP（0x90）替换可疑字节以“去花”：将花指令用 NOP 填充，常见做法是在 IDA 中选中字节 -> 右键 -> Patch program -> Change byte。
  3. 重新分析：在 IDA 中按 c（Convert to code）或使用重新分析命令；按 p 生成函数；按 F5 做反汇编视图检查结果。
  4. 迭代修正：如果仍有异常，继续定位并 NOP 更多可疑字节，直到反汇编连续且逻辑合理为止。

注意：直接在运行中的程序上修改内存（patch）可能改变程序行为，请先在脱机副本或调试器中验证替换不会影响实际执行路径。

常用技巧与提示

  • 使用十六进制查看器或 IDA 二进制视图比单纯 ASM 视图更容易发现数据字节（例如连续的 0x00、0xE8、0xCC 等）。
  • 对于递归下降被干扰的场景，分析者可以从已知的真实函数边界、字符串引用、导入/符号等处强制建立正确的代码段。
  • 留意异常的控制流：大量不可到达或无限循环的跳转可能是花之令的迹象。
  • 对付 call+pop 技巧：识别 call 后紧跟 pop 的模式，并检查返回地址、栈平衡是否合理。

IDA 操作示例

替换单字节为 NOP（在 IDA GUI 中）：

  1. 选中要修改的字节
  2. 右键 -> Patch program -> Change byte
  3. 输入 90（即 0x90 为 NOP）并确定

重新分析与生成函数：

  • 在 ASM 视图按 c 将数据区转换为代码
  • 在可能的函数开始位置按 p 生成函数
  • 按 F5 切换到伪代码/反汇编（Flow）视图检查

总结

花之令本质上是把代码与数据混淆或插入不可执行的字节来误导反汇编器。常见应对策略是：

  • 观察异常控制流与不可到达块
  • 用 NOP（0x90）替换可疑字节，重新分析
  • 根据字符串、导入、已知函数签名强制修复函数边界

小结：手工清除花之令是一个迭代过程，需要结合静态观察与动态验证。

SMC混淆

SMC基本原理：

是在编译可执行文件时，将需要加密的代码区段（如函数、代码块） 单独编译成一个section（段），
并将其标记为可读，可写，不可执行，然后通过某种方法在程序运行的时候将section解密为可执行代码，
并将其标记为可读、可执行、不可写。这样就不能直接在内存里面找到加密的代码，从而无法执行或修改加密的代码

如何识别：

SMC的实现是需要对目标内存进行修改的，.text一般是没有写权限的。
那么就需要拥有修改目标内存的权限：
在Linux中，可以通过mprotect函数修改目标内存的权限
在Windows中，VirtualProtect函数 实现内存权限的修改

mprotect函数：

int mprotect(void *addr, size_t len, int prot);
mprotect()系统调用修改起始位置为addr，长度为length字节的虚拟内存区域中分页上的保护。
addr取值必须为分页大小的整数倍，length会被向上舍入到系统分页大小的下一个整数倍。
prot参数是一个位掩码。

SMC一般有两种破解方法

第一种是找到对代码或数据加密的函数后通过idapython写解密脚本。

第二种是 动态调试 到SMC解密结束的地方dump出来。

第二种比较用于简单的smc加密：
先找到被改变的函数，调试中，将该函数定义取消(IDA中按u)，然后点击函数名按p
重新编译函数，就可以看到内存被改变的函数了
