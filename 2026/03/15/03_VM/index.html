VM

VM

VM = Virtual Machine(虚拟机）在ctf中又叫**[自定义指令集虚拟机]**，也常被叫[字节码虚拟机/沙箱虚拟机VMProtect]

白话：程序作者没有让 CPU 直接执行 x86/x64 汇编指令，而是自己「发明」了一套全新的、只有这个程序认识的「伪汇编指令（字节码）」，然后写了一个「解释器 (VM)」，让这个解释器去逐条解析、执行这套自定义指令

正常的逆向题：程序编译后，直接是 CPU 能识别的 x86/x64 原生汇编指令（比如mov/ push/ pop/ add/ call），你用 IDA/GDB 打开，直接能看到熟悉的汇编代码，能直接看懂逻辑、找 flag。

VM 保护的逆向题：

程序编译后，核心逻辑不再是原生汇编，而是：

  1. 作者写了一堆 自定义的字节码指令（比如0x01=赋值、0x02=加法、0x03=比较、0x04=循环，指令值 / 含义都是作者自己定的）；
  2. 这些字节码指令，被打包成一段指令流，藏在程序的某个地方（内存 / 数据段）；
  3. 程序的主逻辑，就是一个 VM 解释器（随便一个函数可能就是这个解释器的核心！）；
  4. 程序运行时：CPU 只执行「VM 解释器」的原生汇编，解释器再逐条解析、执行自定义的字节码指令，最终完成核心功能（比如校验 flag）。

核心一句话：VM 是「套娃」，CPU 执行解释器，解释器执行自定义指令，你要逆向的是「自定义指令的含义」+「指令流的逻辑」。

程序运行时通过解释操作码(opcode)选择对应的函数(handle)执行。

一套 VM 虚拟机 = 5 个固定组成部分

常见的是**vm_init**代表的是对虚拟机的环境进行初始化的部分

其次就是**dispatcher部分，用于解释opcode取指并分发，就是通过opcode**来进行自定义操作的指令
