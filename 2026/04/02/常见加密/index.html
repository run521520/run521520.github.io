常见加密方式

RC4加密算法

简介

RC4 是一种字节流对称加密算法，加密和解密使用相同的密钥，通过生成与明文等长的伪随机密钥流与明文按字节异或实现。

特性与安全性

  • 实现简单、速度快。
  • 支持 1–256 字节的密钥长度（8–2048 比特）。

注意：RC4 在某些协议和实现下存在偏差问题（历史上在 TLS 中发现过弱点）。生产环境应优先使用经过广泛审计的现代算法（如 AES-GCM）。

算法组成

  1. 初始化算法（KSA）— 根据密钥初始化并打乱 256 字节的 S 盒。
  2. 伪随机生成算法（PRGA）— 基于 S 盒生成密钥流并与数据异或加密/解密。

TEA加密算法

TEA、XTEA、XXTEA算法采用64位的明文分组和128位的密钥。算法中使用了一个神秘常数δ（delta），它来源于黄金比率，用于保证每一轮加密都不相同。δ的精确值并不关键，通常定义为δ=「(√5 - 1)2^31」（即0x9E3779B9），在做题中可能会变，但没有影响。

密钥长度

TEA：使用128位密钥。

XTEA：通常使用128位或256位密钥。

XXTEA：密钥长度更灵活，可以使用任意长度的密钥。

 加密轮数

TEA：通常进行32轮加密。

XTEA：默认进行64轮加密。

XXTEA：加密轮数更多，具体轮数取决于数据块和密钥的长度。

加密算法

XTEA：在TEA的基础上增加了更多的变量和操作，例如密钥的不规则混合。

XXTEA：进一步改进了轮加密过程，使用了更多的变量和操作，并且利用相邻字进行加密。

简介

TEA（Tiny Encryption Algorithm）及其变体 XTEA、XXTEA 是一类轻量级分组/块加密算法，通常以 64 位明文分组、128 位密钥为基础。算法使用常数 delta（δ = 0x9E3779B9，来自黄金比相关表达）作为轮常数。

主要差异

  • TEA：经典实现，通常 32 轮。
  • XTEA：对 TEA 的改进，轮数与细节不同，常见实现轮数更多。
  • XXTEA：适用于任意长度数据块的改进版本，结构更复杂。

常量与符号

  • delta（δ）: 0x9E3779B9

AES加密算法

AES算法是对称算法的一种，是用来替代之前的DES加密算法的。
AES加密算法采用分组密码体制，明文分组的长度为128位即16字节，密钥长度可以为16，24或者32字节(128，192，256位)，
根据密钥的长度，算法被称为AES-128，AES-192或者AES-256

AES算法涉及的主要操作分四种：字节替换、行位移、列混淆、轮密钥加

无论是明文还是密钥，16个字节(128位)的字符，在加密的过程中都是以44的矩阵形式存在
这个矩阵要求输入的字符要从上到下从左到右
之后：
字节替换
将矩阵中的元素换掉，按照S-BOX，去映射其中对应的值
行位移
规则是矩阵的第一行不变，第二行向左移一个字节，第三行移两个字节，第四行移三个字节
列混淆
规则是左乘一个给定的44矩阵，注意这个矩阵是程序设计时给定的
可能每个程序使用的AES算法中的这个矩阵不一定相同
轮密钥加
对于完成列混合的矩阵进行轮密钥加
规则是对完成列混合的矩阵和轮密钥矩阵对应的元素进行异或

之后便是轮密钥矩阵了，然后便没有了。

具体过程：
1.密钥扩展KeyExpansion(key,key1)，主要是从16字节主密钥key生成11个轮密钥key1
2.初始轮密钥加AddRoundKey(flag, key1, 0i64)
3.九轮主循环，每轮循环要经过字节替换SubBytes(flag)，行位移ShiftRows(flag)，列混合MixColumns(flag)，轮密钥加AddRoundKey(flag,key1,i)
4.第十轮字节替换SubBytes(flag)，行位移ShiftRows(flag)，轮密钥加AddRoundKey(flag, key1, 10i64)

AES加密算法的模式主要有五种，它们是ECB模式、CBC模式、CFB模式、OFB模式和CTR模式。
它们之间的主要区别在于加密过程中明文和密文的处理方式以及安全性特点：

ECB模式：
每个明文块被独立加密，相同的明文块得到相同的密文块。
不适合加密大量数据或具有重复模式的数据，容易受到攻击。

CBC模式：
使用前一个密文块对当前明文块进行加密，增加了随机性，相同的明文块在不同位置得到不同密文块。
需要使用初始化向量（IV）来增加安全性。

CFB模式：
使用前一个密文块作为输入生成伪随机密钥流与明文进行异或运算得到密文。
可以支持实时加密和流加密。

OFB模式：
类似于CFB，使用前一个密文块生成伪随机密钥流，然后与明文进行异或运算。
对加密和解密中的错误更加鲁棒，但不支持部分更新。

CTR模式：
使用一个计数器与密钥输入加密算法生成伪随机密钥流，与明文进行异或运算。
可以并行加密和解密，适用于需要高效加密的场景。
选择哪种模式取决于具体应用的需求和安全性要求，例如需要实时加密或流加密的场景可选用CFB模式，而需要高效加密的场景可选用CTR模式。

DES使用56位的密钥和64位的明文块进行加密。DES算法的分组大小是64位，因此，如果需要加密的明文长度不足64位，需要进行填充；
如果明文长度超过64位，则需要使用分组模式进行分组加密。虽然DES算法的分组大小是64位，
但是由于DES算法的密钥长度只有56位，因此DES算法存在着弱点，容易受到暴力破解和差分攻击等攻击手段的威胁。
因此，在实际应用中，DES算法已经不再被广泛使用，而被更加安全的算法所取代，如AES算法等。

DES分两步骤：初始置换，加密轮次

具体过程：将输入的数据进行初始换位(IP)，即将明文M中的数据排列按一定规则重新排列，
已打乱原来的次序。然后将变换后的数据平分为左右两部分，左边记为L0，右边记为R0，
然后对R0实行在子密钥(由加密密钥产生的)控制下变换f，结果记为f(R0,K1),在与L0做逐位异或运算，
其结果记为R1，R0则作为下一轮的L1.如此循环16轮，最后得到L16，R16，实行逆初始化置换1/IP,即可得到
加密数据
解密过程与此类似，不同之处仅在于子密钥的使用顺序正好相反

明文 -> 初始置换(IP) -> 16轮Feistel函数 -> 最终置换(1/IP) -> 密文

DES简单理解就是将8字节明文，用64位密钥(有效密钥56位)加密，变为8字节密文过程

子密钥的生成：
1.将64位整数密钥转换为64个bit的数组，便于后续操作，
2.然后便是PC-1(64位->56位) 从64位中选出56位有效密钥位(去掉每个字节的第8位)，赋值给result
3.将56位分割为左右两部分L,R，用循环的方式，将左右部分储存起来
4.经过16轮循环,每次循环中，将左右部分左移(根据左移位表)，再28次循环合并成56位，
再进行PC-2置换(从56位->48位)得到48位子密钥result，最终会生成16个48位子密钥，储存在父级的变量中

接着就是flag的输入和分配内存了，这里有一个知识是：
DES需要处理的8字节，所以在分配内存时需要向上取巧 (长度+块大小-1)/块大小，这样内存便不会浪费

明文加密：
1.还是将64位明文转换为64位bit数组
2.置换IP,就是将明文位置按规则换一下
3.用32次循环将IP数组分为左右两部分L0,R0
4.16轮Feistel加密，feistel公式：
L[i] = R[i-1]
R[i] = L[i-1] ⊕ F(R[i-1], K[i])
5.循环左右交换并合并(就是左右换一下位置，因为feistel函数会交换左右部分)
6.最终置换IP-1,返回64位整数(将数组转换一下)

MD5算法

简介

MD5（Message Digest Algorithm 5）是一种广泛使用的单向散列算法，主要用于生成固定长度的哈希值（128位）。它的主要特点包括：输入任意长度数据，输出固定长度的哈希值；具有不可逆性；不同输入通常会生成不同的哈希值。

MD5 常用于以下场景：

  • 数据完整性校验：验证文件或数据在传输过程中是否被篡改。
  • 密码存储：将用户密码的 MD5 值存储在数据库中，避免直接存储明文密码。
  • 数字签名：通过 MD5 生成摘要信息，用于验证文件的真实性。

尽管 MD5 曾被广泛使用，但其安全性已被证明存在严重缺陷：

  • 碰撞攻击：可以找到不同的输入数据生成相同的 MD5 值。
  • 彩虹表攻击：通过预计算常见密码的 MD5 值，快速破解密码。
  • 不适合高安全性场景：如 SSL 证书和数字签名。

由于 MD5 的安全性问题，建议在高安全性场景中使用更安全的哈希算法，例如 SHA-256 或 SHA-3。这些算法提供更强的抗碰撞性和更高的安全性。

原理

MD5 的核心是将输入数据分组为 512 位的块，每块再细分为 16 个 32 位子分组。通过四轮循环运算（FF、GG、HH、II 函数），最终生成 128 位的哈希值。具体步骤如下：

  1. 填充数据：将输入数据填充到长度对 512 取余为 448 位，填充方式为在末尾加一个“1”，后续补“0”。
  2. 附加长度信息：在填充后的数据末尾添加 64 位，表示原始数据的长度。
  3. 初始化缓冲区：使用四个 32 位的常量（A=0x67452301, B=0xefcdab89, C=0x98badcfe, D=0x10325476）作为初始值。
  4. 分组处理：对每个 512 位分组进行四轮循环运算，每轮使用不同的非线性函数（F、G、H、I）和常量。
  5. 输出结果：将最终的 A、B、C、D 拼接，生成 128 位的哈希值。

SM4加密算法

SM4是中国国家密码管理局发布的对称分组加密算法，分组长度与密钥长度均为128位，采用32轮非线性迭代结构，广泛应用于金融、政务、物联网等需要符合国密标准的场景。它支持ECB、CBC、CTR等模式，其中CBC模式因安全性较高而被推荐使用。

以CBC模式为列：

准备密钥：初始的密钥长度为16字节（128位）通过密钥扩展算法生成32个32位轮密钥

明文填充：就是说明文的长度必须为16字节的倍数，不足就用PKCS#7填充，运算以16字节为一组

加密流程：

  • 明文分为4个32位字（X_0，X_1，X_2，X_3）

  • 密钥扩展：将初始密钥通过非线性变换生成32个轮密钥。

  • 迭代加密：明文分组经过32轮非线性变换，每轮使用一个轮密钥。

  • 密文输出：最终迭代结果经逆初始变换生成密文。

  • S盒（SboxTable）：16×16的字节替换表，用于非线性变换。
  • 固定参数：FK（初始密钥扩展常量）和 CK（轮密钥生成常量）。
  • 轮函数与密钥扩展：通过 sm4Lt、sm4F、sm4CalciRK 等函数实现。
  • SetKey：生成32轮加密密钥。
  • OneRound：单轮加密/解密操作。
  • Enc和Dec：实现CBC模式的分组处理。

加密：

  1. 填充数据到16字节倍数（PKCS#7填充）。
  2. 每块与前一块密文（或IV）异或后加密。

解密：

  1. 解密后与前一密文块（或IV）异或。
  2. 移除填充，末尾置零。
